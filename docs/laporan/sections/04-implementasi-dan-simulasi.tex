\section{Implementasi dan Simulasi}
Implementasi utama OATSIDE ditulis dalam bahasa Python 3.10, tetapi putaran kompresi SHA-256 Customised juga diimplementasikan dalam bahasa C untuk meningkatkan performa\footnote{Awalnya kami menggunakan sepenuhnya pakaii Python, tetapi \textit{overhead} interpreter Python membuat fungsi ini menjadi bagian paling lambat dari cipher. Versi C terdapat pada \texttt{src/native/oatside\_sha.c} dan menghasilkan keluaran yang identik dengan versi Python.}. Pustaka hasil kompilasi C bersifat opsional. Apabila pustaka tersebut tidak tersedia, program secara otomatis menggunakan implementasi Python. Seluruh cipher, mode operasi, dan \textit{padding} diimplementasikan sendiri tanpa pustaka kriptografi pihak ketiga.

\subsection{Hasil Uji Coba}
Uji coba dilakukan melalui CLI pada Linux (kernel 6.12) dengan Python 3.13 dan pustaka C yang dikompilasi menggunakan GCC 14.2. Kunci yang digunakan adalah \texttt{0x1234567890ABCDEF}, IV/\textit{counter} adalah \texttt{0x0011223344556677}, ukuran blok 64 bit, dan 16 putaran. Setiap berkas dienkripsi lalu didekripsi dengan kelima mode, kemudian nilai SHA-256 berkas hasil dekripsi dibandingkan dengan berkas asli. Hasilnya ditunjukkan pada Tabel \ref{tab:hasil_uji}.

Seluruh 40 kombinasi berkas dan mode menghasilkan berkas dekripsi yang identik byte demi byte dengan berkas asli. Berkas \textit{byte} \texttt{00}--\texttt{FF} berisi seluruh nilai byte dan deretan panjang byte \texttt{00} serta \texttt{FF} untuk memastikan program tidak mengasumsikan teks UTF-8. Pengujian yang sama untuk berkas ZIP dengan ukuran blok 96, 128, dan 192 bit pada kelima mode juga menghasilkan berkas yang identik. Selain itu, rangkaian pengujian otomatis (\texttt{python -m unittest discover -s tests}) yang berisi 42 kasus uji, termasuk uji konstruksi mode yang dihitung terpisah dari implementasi mode, lulus seluruhnya.

Waktu enkripsi melalui CLI untuk gambar PNG berukuran 139.719 byte adalah sekitar 11,5--12,2 detik pada setiap mode, atau sekitar 11--12 KB/s. Waktu dekripsi hampir sama. Kecepatan ini dipengaruhi oleh rancangan OATSIDE yang memanggil 64 kompresi SHA-256 untuk setiap blok.

\subsection{Verifikasi Integritas}
Integritas pada program ini diartikan sebagai jaminan bahwa hasil dekripsi identik dengan data asli apabila kunci, mode, dan IV yang digunakan sama. Ini dibuktikan melalui perbandingan nilai SHA-256 pada Tabel \ref{tab:hasil_uji}. Ada bberapa kondisi kesalahan juga diuji sebagai berikut.
\begin{itemize}[noitemsep]
    \item Dekripsi ECB dengan kunci yang salah satu bitnya berbeda ditolak dengan pesan \textit{padding} PKCS\#7 tidak valid.
    \item Perubahan satu bit pada byte terakhir cipherteks CBC ditolak dengan pesan \textit{padding} tidak valid.
    \item Cipherteks CBC yang panjangnya bukan kelipatan ukuran blok ditolak sebelum dekripsi dilakukan.
    \item Perubahan satu bit pada cipherteks CTR tetap didekripsi tanpa pesan kesalahan, dan menghasilkan satu bit yang berbeda pada posisi yang sama di plainteks.
\end{itemize}

Nah, kasus terakhir menunjukkan bahwa program tidak menyediakan autentikasi cipherteks. Penolakan karena \textit{padding} tidak valid hanya terjadi secara kebetulan pada ECB dan CBC, sehingga tidak dapat dianggap sebagai mekanisme pendeteksian manipulasi. 

\subsection{Analisis}
Hasil uji coba menunjukkan bahwa kelima mode operasi berjalan dengan benar untuk file teks dan biner, termasuk file kosong dan file yang ukurannya tepat di batas blok. Perbedaan panjang cipherteks sesuai dengan rancangan, yaitu ECB dan CBC menambahkan 1 sampai 8 byte \textit{padding}, sedangkan CFB, OFB, dan CTR menghasilkan cipherteks dengan panjang yang sama dengan plainteks. Mode CFB, OFB, dan CTR lebih cocok untuk data yang panjangnya tidak boleh berubah, sedangkan ECB tidak disarankan untuk data dengan pola berulang karena blok plainteks yang sama menghasilkan blok cipherteks yang sama. Keterbatasan utama program adalah kecepatan, yaitu sekitar 11--12 KB/s, sehingga program lebih sesuai untuk file berukuran kecil hingga sedang.
